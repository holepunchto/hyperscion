- **Best:** `hs land --check "npm test"` plus `hs watch --path /CHANGE-REQUEST.md --count 1` made the whole loop trivial: the wait returned the moment pm landed CR-1, and `hs claims` immediately showed `suggested lead: a3` and the ann approval rule, so I knew not to touch it. `hs status`/`hs log` tagging `[final]` made it clear when #49 was safe once the hub returned.
- **Worst friction:** a NOTES.md-only land (merge=union file) got undone while the hub was down:
  `hs land -m "a1: NOTES on CR-1 ..." --check "npm test"` -> `landed #62` then `!! your land #62 was undone: a concurrent land on the same files came first. ... hs sync ... then hs land again` (EXIT 1). Printing `landed #62` before `undone` in the same output is momentarily confusing, and for an append-only union file an automatic re-land would have been safe. `hs sync && hs land` fixed it (`#87 final`).
- **Most wanted:** `hs land --retry` (or automatic for union-merged-only changes): on an undo, sync and re-land in the same command.
