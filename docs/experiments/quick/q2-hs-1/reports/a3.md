# a3 report (pricing / report / cli / integration)

- **Best:** once the hub was healthy, plain `hs land` was fast and unambiguous: per-file auto-rebase over concurrent NOTES.md appends (`main moved: /NOTES.md (#376 pm) ... rebasing ... merged teammates' changes ... landed #377 / #377 final`), and `hs watch --path /src/scheduler.js --count 1` was a clean way to block on a2's scheduler. `hs show 376` made the pm change request instantly readable.
- **Worst friction:** my first `hs land -m "pricing: ..." --check "npm test"` never finished. With ~20 swarm writers landing constantly it looped `check passed in 0.3s` / `main moved to #63 while checking; checking again` (then #65, #66 ...), then hit the hub outage: `!! 6 file(s) on main could not be fetched: no online peer holds it ... /CONTRACTS.md (blobs z3bwxhey5j)` and `hs: content for /CONTRACTS.md is not available from any connected peer; nothing was changed` (exit 1). The retry passed the check 3 more times (`main #161 ... #204 ... #245`, all "main moved ... checking again") until my 240 s timeout killed it. Meanwhile `hs status` refused to run (`another hs process is using this worktree (e.g. hs seed running here)`) and `hs doctor` hung >60 s. Fix: I ran `npm test` locally and used plain `hs land` (landed #323 final in seconds). ~6-7 min lost. Also a `watch --path /src ... --timeout 120` timed out with 0 matches although a2's #381 (src/scheduler.js) landed around then.
- **Most wanted:** `--check` should only re-run when main changes paths that overlap the checked tree (or are imported by it), not on every unrelated `/swarm/` changeset; plus read-only `status`/`doctor` should work while a `land` is running.
