# a2 report (scheduler)

- **Best:** `hs land --check "npm test"` handled a concurrent CONTRACTS.md edit by itself: "main moved to #62 while checking (/CONTRACTS.md #62 a1); checking again / merged teammates' changes into your edits ... landed #65". I never had to resolve anything by hand. `hs watch --path ... --count 1` was a clean way to wait for a1's geo.js and the CR.
- **Worst friction:** the hub was down for my first land. `hs land` printed `#38 provisional: the hub is not reachable, so it settles once the hub is back`, and `hs status` printed `!! hub not settling: lands after #36 have been provisional for 21s ... the team owner replaces it: hs add-writer <new key> --indexer` (the second half is scary text that an agent can't act on). Later `#65` came back as `your land #65 is now #66 (reordered when peers met; nothing lost)`, which was clear but meant my first seq number was wrong. Smaller point: a wait for a path that had already landed returned at once ("already on main before this wait"), which was correct but easy to misread as a timeout. Separately, CR-1 got done three times (a1 geo.flightMinutesTo, my trip.flightMinutes, and a3 computing the minutes inside pricing). That was a coordination failure, not an hs one.
- **Most wanted:** `hs status`/`land` should say which seq a provisional land will most likely end up at, and give a `hs wait-final <seq>` for a land made earlier. Also helpful: a feed view that hides /swarm/ noise (`hs watch --exclude /swarm/`).
