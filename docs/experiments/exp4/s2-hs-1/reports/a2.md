## 2. How I learned about teammates' work

- Background `hs watch --json >> .hs/feed.jsonl` all run; I read it with `cat`/`tail`/`grep -v settled` before each step (~8 times).
- For waiting I used `hs watch --path ... --count 1 --timeout 580` (5 times). This was the best part: zero polling, it returned the moment a3 / pm / a4 landed on my paths, and the one-line summary was usually enough to decide whether to `hs show`.
- `hs show 5 --path /NOTES.md`, `hs show 5 --path /CONTRACTS.md`, `hs show 9`, `hs show 18 --path /src/scheduler.js`, `hs show 19 --path ...` to read diffs; `hs cat /src/scheduler.js` once (see friction). `hs sync` output's "incoming from teammates" list was a good summary.
- Yes, the watch feed fully replaced polling.

## 5. Friction, bugs, confusing output

- `hs cat /src/scheduler.js` (before syncing, with #5 already in my feed) printed the **old** TODO stub, not a3's #5 version. The playbook says `cat` is "the latest landed version of a file, without touching your worktree". It apparently shows my synced base (or what's fetched), silently. Confusing; I briefly thought a3 hadn't touched the file. It should fetch or at least say "showing #4, main is at #7".
- Before syncing I had to `hs restore src/scheduler.js` my local edits to avoid "changed on main but also edited here"; there's no `hs stash`, I backed up the file manually.
- The conflict exit left 4 paths "committed, not landed" in `hs status` — fine, but it wasn't obvious whether re-landing needed `hs commit` first (it didn't).
- `hs watch --timeout` exit 2 on timeout prints `watch: timed out after 580s with 0 matching changeset(s)` — clear.
- No bugs otherwise; outputs were concise and accurate.

## 6. Compared with git

- Better: `hs watch --path X --count 1` is a real "wait for teammate" primitive; with git I'd poll `git fetch` in a loop. Per-file lands with automatic rebase meant 5 people landing every few minutes had no push-rejected/pull/rebase dance. `--check` on main+mine is a built-in pre-merge CI that git lacks without extra tooling. Union-merged NOTES.md just worked (with git it would conflict constantly unless `.gitattributes merge=union` set up).
- Same: the one real conflict was handled like git (markers). The a3/a2 design crossing would have happened with git too — it's a communication problem, not an SCM one.
- Worse: `hs cat` silently stale; no stash; no branch/PR UI for discussing a design before landing (I used NOTES instead; `hs propose` exists but I didn't need it). Git tooling (blame, bisect, IDE integration) is much richer.
- Net: for this exact situation (parallel agents, shared files, frequent small lands) hs was somewhat better than a shared git repo.
