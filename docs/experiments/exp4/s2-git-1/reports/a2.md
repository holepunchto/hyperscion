  scheduler.js, CONTRACTS.md, NOTES.md or my files; `git show <sha>:src/scheduler.js` once to

## 5. Friction and confusing output

- `git pull` with rebase conflict leaves you in `interactive rebase in progress; onto b7448ea` — I never asked for an interactive rebase; and `Could not apply d792435... # scheduler: ...` with a stray `#`.
- Git happily lets you `git add` + `git commit` a file full of `<<<<<<<` markers mid-rebase. No warning. Then `git push` says `fatal: You are not currently on a branch. To push the history leading to the current (detached HEAD) state now, use git push origin HEAD:<name-of-remote-branch>` — the suggested action would have pushed a conflicted commit to a new branch; nothing says "you are mid-rebase".
- `git checkout --ours` during a rebase means upstream (a3's) version, `--theirs` means mine. I knew it, but had to stop and think.
- Rejected push output, if you only see the tail, is `hint: See the 'Note about fast-forwards' in 'git push --help' for details.` — the actual `! [rejected]` line is earlier.
- No way to know that a teammate is *currently* working on the same function (a3 and I fixed the same bug in parallel even though a3 announced it, because the announcement arrived while I was mid-edit).
- Conflict on scheduler.js was a whole-file "both added" style conflict (a3's 212-line file vs my 124-line skeleton), not a small hunk; resolution meant re-reading a3's whole file.

## 6. Compared with an ideal tool

Disclosure: early in the run a harness hook auto-injected the hs playbook (docs/AGENTS.md) into my context. I did not use it for the work, but it may have shaped this section and section 7.


- A **live feed** of pushes and NOTES lines (push-based) instead of fetch loops that wake on any commit; filterable by path ("tell me when scheduler.js, CONTRACTS.md or NOTES lines mentioning a2 change").
- **Intent / claim visibility**: "a3 is editing scheduleTimes area / took bug X" visible before code lands, so the duplicate fix and the duplicate scheduler skeleton would not happen.
- **Guard rails on landing**: refuse to commit/push files with conflict markers; land = pull + test + push atomically (`--check "npm test"`), retrying itself when main moved, instead of my manual `pull && npm test && push` that got rejected twice.
- **Section-level ownership in a shared file** (a3 capacity / a2 timing) so concurrent edits to different halves merge automatically and a "Show" goes to the other owner automatically when I touch their half.
- Read-only "what changed in my area since I last looked" that doesn't depend on me remembering to re-read NOTES after every pull (I missed a4's "nothing needed" line that way).

## 7. Features I wanted

- Commit-marker check in the commit step.
