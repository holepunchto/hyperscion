# a4 report (git arm): pricing + report

## 1. What I built
- `src/pricing.js`: `price(plan, day) -> { currency: 'EUR', prices, total, lines }`, `pricePackage(...)`, `PRICING` constants. Formula pinned in CONTRACTS.md in my first push (a2296e3): 2.50 + 0.80/km (great-circle, home depot -> destination) + 0.50/kg + 3.00 express, half-up to cents, total summed in integer cents.
- `src/report.js`: `renderReport(plan, prices, day)` (text: per drone trips, stops with hh:mm ETAs, weights, prices, express/window flags, idle drones, unassigned with reasons, totals) and `reportJson(...)` (JSON-friendly superset of the cli `--json` contract). Uses the Plan's own `stops[].arrive`, `end`, `distanceKm` when present, else computes them.
- Tests: `test/pricing.test.js`, `test/report.test.js` (hand-made plan, plus one test over the real pipeline loadDayFile -> plan -> price -> report on day1, plus a regression test for the double-rounding bug). Final main: 68 pass, 0 fail; `node src/cli.js plan fixtures/day1.json` prints a sensible report; checked all edge fixtures by hand.

## 5. Friction and confusing output
- Outage message: `fatal: '/.../unreachable.git' does not appear to be a git repository` / `fatal: Could not read from remote repository. Please make sure you have the correct access rights and the repository exists.` reads like a misconfigured remote or permissions problem, not "server is down, retry later". Only the playbook table told me what to do. I had to check `git remote -v` to see what was going on (the URL itself had changed, which I did not touch).
- `Rebasing (1/1)Successfully rebased and updated refs/heads/main.` printed on one line (progress CR without a TTY).
- Rejected push with my output filter only showed `hint: See the 'Note about fast-forwards' in 'git push --help' for details.`; the actual "rejected" line is earlier and verbose. The useful fact (someone pushed, retry) is buried in hints.
- `Current branch main is up to date.` vs `Already up to date.`: two phrasings for the same state from pull.
- While origin was down I was blind: 15 commits including the Plan shape I was coding against landed and I could not see any of them.

## 6. Compared with an ideal tool
- A feed / subscription: "notify me when CONTRACTS.md section scheduler or anything mentioning a4 changes" instead of fetch loops. Teammates' bug reports against my file came as NOTES lines I had to grep for.
- Offline-tolerant peer sync: when the central origin is down, I should still be able to see and exchange teammates' commits peer-to-peer. With git + one origin, the whole team stalls/blinds at once.
- Automatic "land" = rebase + run tests + push, retried atomically, so the "pull && npm test && push" race (my one rejection) disappears.
- Ownership-aware messages: "your file src/report.js was mentioned/touched by a2" rather than discovering it by reading.
- Clear distinction between "remote unreachable (transient)" and "remote misconfigured".

## 7. Features I wanted
- Push notifications / watch on paths and on mentions of my agent id.
- Structured per-module contract entries (machine-readable), so a Plan shape change is a typed event, not prose.
- A built-in "land" command with test gate and auto-retry.
- Peer fallback when origin is down.
