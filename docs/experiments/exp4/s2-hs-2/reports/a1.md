## 5. Friction, bugs, confusing output

- `hs watch --path ... --timeout 600` blocks for exactly 600 s, which equals the agent shell's 600 s tool limit, so my last wait got moved to background by the harness right as it timed out. The tool itself was fine (`watch: timed out after 600s with 0 matching changeset(s)`, exit 2). Keep timeouts below the harness limit.
- `hs status` after a long wait: `main is at #39 or later (from your feed); this shows #36. `hs fetch` to update`. This is clear, but it suggests `hs fetch` where I wanted `hs sync`. It was slightly unclear whether fetch alone updates my working files (the playbook says sync does).
- The feed has `review` events for other people's changesets (`"@ #13 approved by a5"`), mixed into my changeset feed with no "for-me" filtering in the JSON. That is harmless but noisy.
- The first `land --check` said "checking main #5 + your changes" and then "landed #6". I needed a second to realise #5 was the base and #6 my new changeset. Fine once understood.
- No bugs hit.

## 6. Compared with git

For my role (upstream module, own files only), hs was somewhat better than a shared git repo.
- `watch --path X --count 1` replaces a `git fetch` loop plus diff filtering.
- `land --check` does fetch+rebase+test+push in one step, which with git would have meant pull --rebase / test / push retries while four others pushed. I hit 4 incoming changesets on my very first land, which with git is a guaranteed non-fast-forward rejection plus a manual rebase.
- The union merge on NOTES.md removed the most common git conflict in this setup (everyone appending to one log).
- `hs show n --path` is about the same as `git show n -- path`. `hs cat` is about the same as `git show origin/main:path`.

Where git is as good or better:
- Mature tooling: `git log -S`, blame, and branch visualisation.
- Familiarity.
- Git's merge-conflict UX is known.

My workload had zero conflicts, so I can't judge hs's conflict handling. With all files owned per agent, git would also have been mostly conflict-free; the win is speed and less ceremony, not correctness. Review (Show/Ask) didn't come up for me since I touched nobody else's files.
