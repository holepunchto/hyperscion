# a4 report: pricing + report

## 1. What I built

- `src/pricing.js`: `price(plan, day) -> { currency, rates, prices, lines, total }`, `pricePackage`, `RATES`, `toCents`. The formula is pinned in CONTRACTS.md: EUR 2.50 + 0.40/km (great-circle distance from the carrying drone's home depot to the destination, one way) + 0.75/kg + 3.00 express. Each package is rounded half-up to whole cents once, and the total is a sum of integer cents.
- `src/report.js`: `renderReport(plan, prices, day) -> string` shows each drone with its trips (depart/back, km, load), its stops in flight order (ETA = handover time `depart - serviceMinutes`, weight, priority, price, window, and a hover note when the drone waits for a window), idle drones, per-drone subtotals, unassigned packages with reasons, and totals. `reportJson()` is the `--json` payload. It holds the four pinned cli fields plus currency/date/city/stats/drones.
- Tests: `test/pricing.test.js` and `test/report.test.js`. They cover hand-made fixtures and the real pipeline over day1 and the edge fixtures. The suite has 65 tests and all were green on main #29. On day1, 18 packages are delivered in 11 trips for EUR 115.48, and p19 is unassigned as too heavy.

- **#2 (a3, Plan shape)**: trips carry `depot`, `stops[{package, arrive, depart}]`, `distanceKm` and `loadKg`. I built the report's per-stop ETAs and trip header directly on that, without a hand-made guess.
- **#4 (a1, Day shape)**: `drone.home` exists, so pricing uses `drone.home` before looking up the depot. The `*ById` maps let my lookup helper accept arrays or maps.

## 4. Conflicts, rebases, flips

- I had no real conflicts, no undone lands and no reorgs.
- Twice `--check` printed `main moved to #5 while checking; checking again` (and #21). It re-ran the check and landed cleanly.
- I got no `main moved: /X ... rebasing` messages, because nobody else touched my files. Shared files (CONTRACTS.md, NOTES.md) merged silently each time.
- Every land ended `#n final` within seconds.

## 5. Friction, bugs, confusing output

- I hit essentially no bugs.
- `hs watch --for-me --count 1 --timeout 180` exited 2 with `watch: timed out after 180s with 0 event(s) for you`. That is documented, but exit 2 ("done, but read the !! lines") for a plain timeout is a slightly odd overload.
- The feed lines are long JSON with 52-character hashes. That is fine for machines but awkward to skim with `tail`. `settled` lines make up about half the feed.
- The `incoming from teammates` list after `land --check` lists changes that were already in the tree when the check ran. That is useful, but it is easy to miss that these entered your worktree only now, after you wrote your code.
- NOTES.md attribution: a3 noted a line "tagged [a3] but written by a5". That was a teammate's mistake, not an hs bug. However, union merge gives no per-line author, so hs cannot help catch it.

## 6. Compared with git

- **Where hs did better:**
  - `land --check` gave me rebase, test on the merged tree, push, and a "final" acknowledgement in one command. Re-checking automatically when main moved is something I'd have to script with git: `pull --rebase && npm test && push`, retrying on a non-fast-forward.
  - The `incoming from teammates` summary and `hs watch --path` (block until a file lands) are better than `git fetch` polling plus `git log origin/main -- src/scheduler.js`.
  - The union merge on NOTES.md avoided the append conflicts that 5 agents would certainly hit in git without `.gitattributes merge=union`.
- **Where git would be equal:** in this run my files were disjoint from everyone else's. Git with small commits and `pull --rebase` would also have produced no conflicts. Most of hs's advantage here is ergonomics and the feed, not merge capability.
- **Where hs falls short of git:** the familiar tooling (blame, bisect, branches for an experiment) isn't there. I didn't need any of it in a ~10-minute run.

## 7. Features I wanted

- `hs watch` text mode with a filter that hides `settled` lines, or `--json --no-settled`.
- A `hs feed` command that prints a compact `#n author files :: message` view of the feed, without me piping `.hs/feed.jsonl` through grep/cut.
- `hs watch --path` that also fires on the contract section of a file. For example, I'd like to be told when someone edits my section of CONTRACTS.md. That isn't possible per file today.
