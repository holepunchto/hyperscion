# a2 report (geo), git arm

## 1. What I built

`src/geo.js` + `test/geo.test.js` (14 tests) and the pinned CONTRACTS "geo" section:
`distanceKm` (haversine, R=6371, accepts points or anything with `destination`),
`travelMinutes`, `routeLengthKm`, `orderRoute` (nearest neighbour + 2-opt, deterministic,
non-mutating), `withinRange`, `reachable`, `tripTimeline` (per-stop
`legKm/arrive/deliver/wait/depart/late`, `returnAt`, `feasibleWindows`) and `planTrip`
(orders stops; if the shortest order misses a window, finds the shortest window-feasible
order: exhaustive for <= 7 stops, else earliest-deadline-first). Tested against raw JSON and
against a1's frozen `loadDay` output. Final main: 68/68 tests pass, CLI prints 18/19
delivered, 12 trips, 116.43 EUR.

## 2. How I learned about teammates' work

- `git fetch -q && git log --oneline --stat HEAD..origin/main` before every commit/push (5 times).
- After each pull I read `CONTRACTS.md` / `NOTES.md` in the working tree (cheaper than `git show`).
- `cat src/scheduler.js` after pulling a3's first scheduler commit (9925de1), and ran the
  real model + scheduler from node to check my functions against their output.
- Bounded fetch loops from the playbook 3 times (waiting for `src/scheduler.js`, then for
  "anything new"); each ended after 2 iterations (~40 s), i.e. about 2-3 minutes of polling
  in total. Teammates were pushing fast, so polling was cheap here; it would not be if a
  dependency were slow.

## 3. Moments where others' pushed work changed what I did

- **ca3f9f6 (a3, Plan shape in CONTRACTS)**, seen in the log when my first push rebased: a3
  pinned per-stop fields `arrive/deliver/wait/depart/legKm` and "hover until `window[0]`"
  semantics. My first `tripTimeline` (2a36c33) had `{stop, arrive, depart}` with arrive
  jumping to the window. I rewrote it in c20e2e9 to emit exactly a3's fields, made window
  waiting the default, and added `late`/`feasibleWindows` plus window-aware `planTrip`.
- **7a373b7 (a1, Day shape)**: `window: null` when absent, `drone.home {lat,lon}`, frozen
  objects. Confirmed geo works on it and added a test (1104793) so a model change that breaks
  geo shows up in my tests.
- **9925de1 (a3 scheduler)**: a3 does greedy insertion with its own `simulate()` and only uses
  `geo.distanceKm` (later `travelMinutes`, 266a80a). I ran `geo.planTrip` on every day1 trip:
  no shorter feasible order exists, so I did *not* push a reordering pass into a3's file;
  posted the finding in NOTES instead. That saved an unnecessary cross-owner edit.
- 9b98ced (a4 pricing switched to `geo.distanceKm` citing my 2a36c33): confirmation my
  contract was being used as written; no change needed.

## 4. Conflicts, rejected pushes, rebases

- 4 pushes to main, 0 rejected, 0 conflicts. 3 pulls rebased my single commit onto new
  teammate commits (`Rebasing (1/1)Successfully rebased and updated refs/heads/main.`),
  all clean, NOTES.md union merge worked every time (5 agents appending concurrently).
- Because I always did `fetch; log; commit; pull; test; push` in one shell line, the window
  for a race was a few seconds; I never hit `! [rejected]`.

## 5. Friction and confusing output

- `Rebasing (1/1)Successfully rebased and updated refs/heads/main.` prints on one line with no
  separator (progress line overwritten by \r in a non-tty). Readable, but ugly.
- The output of the rebase gives no hint *what* I was rebased over; I had to run
  `git log --stat HEAD..origin/main` *before* pulling to know. After the pull that range is
  empty, so the information is gone unless you remember ORIG_HEAD/reflog.
- CONTRACTS.md changed under me during a pull (a3's Plan section). Nothing tells you "a file
  you just edited was also edited by someone else" when the merge is clean; I only noticed
  because my editor flagged it. A clean textual merge of a contracts file is exactly where a
  semantic mismatch hides.
- No notion of "who depends on me": to know whether a3 actually used geo I had to read
  scheduler.js source. `git log -S'geo.'` would work but is not something you think of.
- Polling: the bounded `for ... sleep 20` loop works but is a hand-rolled feed.
- No confusing error messages in this run; nothing broke.

## 6. Compared with an ideal tool

In this exact setup (5 agents, owned files, two shared docs) git was adequate mostly because
ownership was clean and NOTES.md was union-merged. An ideal tool would have:
- pushed a notification when someone changed the CONTRACTS section I depend on or my file's
  consumers changed (instead of me polling and diffing);
- shown, at rebase time, a summary of what came in ("a3 changed CONTRACTS scheduler; a1
  landed model") rather than just "Successfully rebased";
- tracked consumers of an interface (who imports `geo.tripTimeline`) so I would know that
  a3 does *not* use most of my API before investing in it;
- run the full test suite of dependents automatically on my push and told me if I broke
  them (I relied on everyone running `npm test` on top of main).

## 7. Features I wanted

- A push/fetch-triggered feed filtered to paths I care about (`CONTRACTS.md#geo`, `src/geo.js`,
  importers of geo) — a `git watch` with a blocking wait.
- `git pull` printing the incoming `--stat` summary when rebasing (like merge did).
- Per-section ownership / change alerts on shared docs.
- Structured asks ("a3 needs X from a2") rather than free text lines in NOTES.md.
